# Verificação E1.1 — Base do projeto e `gateway doctor`

## Pré-requisitos (uma vez)

1. `git config --global user.name "Seu Nome"` e `git config --global user.email "voce@the12company.com"`.
2. Crie `config.local.yaml` na raiz (gitignored) a partir de `config.example.yaml`:
   - `oracle.dsn`: `host:porta/service` do Oracle de teste (consulte o alias em `C:\oracle\instantclient_23_26\network\admin\tnsnames.ora`).
   - `oracle.user`: usuário somente-leitura.
   - `oracle.password`: `env:ORACLE_PASSWORD` e defina a variável na sessão (`$env:ORACLE_PASSWORD = '...'`), ou a senha literal (o `doctor` emite WARN).
   - `oracle.schema`: owner das tabelas `PC*` se houver mais de um (normalmente vazio).
3. Nunca cole a senha no chat nem em arquivo versionado.

## Automatizado

```powershell
make verify E=1.1
```

Saída esperada: uma linha `PASS`/`FAIL`/`SKIP` por passo e `RESULTADO: PASS` no fim. Os passos que dependem do Oracle são `SKIP` quando não há `config.local.yaml` nem `ORACLE_DSN`.

Acentos no PowerShell: o `gateway.exe` muda o console para UTF-8 quando escreve em um terminal. Ao capturar a saída em script, defina antes `[Console]::OutputEncoding = [Text.Encoding]::UTF8` (o `E1.1.ps1` já faz isso).

| 9 | Push para o GitHub | Workflow `ci` verde em `windows-latest` e `ubuntu-latest`, artefato `gateway-windows-amd64` |

## O que o `doctor` verifica

- **catálogo**: lê `sources/winthor/_waves.yaml` (46 tabelas em 3 ondas).
- **configuração**: DSN, usuário e origem da senha (`env`, `dpapi` ou literal com WARN).
- **conexão**: abre a conexão com timeout; erros são traduzidos (ORA-01017, ORA-12514, ORA-12541…).
- **identidade**: `USER`, `DB_NAME`, instância e host.
- **versão**: `PRODUCT_COMPONENT_VERSION` (ou `V$VERSION` quando acessível).
- **charset**: `NLS_CHARACTERSET` (WARN quando não for UTF-8), `NLS_NCHAR_CHARACTERSET`, `NLS_LENGTH_SEMANTICS`.
- **relógio**: desvio entre `SYSTIMESTAMP` em UTC e o relógio local (WARN acima de 60 s), fusos do banco e da sessão.
- **privilégios de sistema** (`SESSION_PRIVS`): FAIL para privilégios que permitem escrita ou alcançam outros schemas (`UPDATE ANY TABLE`, `CREATE ANY ...`, `ALTER SYSTEM`, `CREATE EXTERNAL JOB`...). WARN, com recomendação de revogar, para privilégios que só criam objetos no schema do próprio usuário (`CREATE TABLE`, `CREATE JOB`, `CREATE CREDENTIAL`, `UNLIMITED TABLESPACE`), pois não alteram as tabelas do Winthor. WARN para leitura ampla (`SELECT ANY TABLE`).
- **papéis** (`USER_ROLE_PRIVS`): FAIL para `DBA`, `RESOURCE` e similares; WARN para papéis desconhecidos.
- **privilégios de objeto** (`USER_TAB_PRIVS` e `ROLE_TAB_PRIVS`): FAIL para qualquer coisa além de `SELECT`/`READ`/`FLASHBACK`.
- **capacidades opcionais** (INFO): `FLASHBACK ANY TABLE`, `DBMS_FLASHBACK`, `DBA_EXTENTS`, `V$SESSION`, `FETCH FIRST` por versão.
- **tabelas**: resolve o owner (`oracle.schema`, sinônimo ou `ALL_TABLES`) e executa `SELECT 1 ... WHERE ROWNUM < 1` em cada tabela; lista as que faltam.
- **arquivos de tabela**: WARN para tabelas sem `<TABELA>.yaml` aprovado (chega no E1.2).

Nenhuma consulta do `doctor` lê linhas de dados das tabelas.
