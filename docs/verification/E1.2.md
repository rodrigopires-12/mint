# Verificação E1.2 — Inventário das tabelas

## O que foi entregue

- `gateway inventory`: lê o dicionário do Oracle (`ALL_TAB_COLUMNS`, `ALL_COL_COMMENTS`, `ALL_CONSTRAINTS`, `ALL_INDEXES`, `ALL_TABLES`) para as 46 tabelas de `_waves.yaml`, cruza com a semente `sources/winthor/_scope.yaml` (colunas que o escopo exige, com proveniência `scope` ou `proposed`) e gera:
  - `sources/winthor/<TABELA>.yaml` com `status: proposed`: colunas extraídas (tipo Oracle e ClickHouse proposto), chave (constraint real, índice único ou proposta), watermark, partição, estratégia, estatísticas, riscos, colunas do escopo ausentes e perguntas.
  - `docs/tables-inventory.md`: resumo, respostas com evidência aos pontos #1, #2, #11, #12, #13 e #14 do escopo e detalhe por tabela (inclui distribuição por mês do watermark).
  - `docs/inventory/<TABELA>.md`: lista completa de colunas de cada tabela (nomes e tipos, sem dados), para escolher substitutas quando faltar coluna.
- Só agregações são lidas (`COUNT`, `MIN`, `MAX`, duplicidade de chave, linhas por mês). Nenhuma linha de dados passa pelo contexto.

## Como gerar

```powershell
make build-windows
dist\gateway.exe inventory              # todas as tabelas, com COUNT(*) e distribuição por mês (varreduras completas)
dist\gateway.exe inventory --no-count   # só dicionário, rápido
dist\gateway.exe inventory --tables PCMOV,PCPREST --months 24
```

Arquivos já aprovados (`status: approved`) são preservados; use `--force` para regenerar.

## Automatizado

```powershell
make verify E=1.2
```

Passos: existe um `<TABELA>.yaml` para cada tabela de `_waves.yaml` (46); todos carregam e validam; `docs/tables-inventory.md` tem as seis respostas; o `doctor` reporta `arquivos de tabela` como OK (todas aprovadas) ou WARN com a contagem de propostas.

## Portão humano

1. Revise cada `sources/winthor/<TABELA>.yaml`: chave, watermark, partição, estratégia e a lista de colunas (as de `use: proposed` são propostas minhas; as de `use: control` servem às exclusões herdadas).
2. Corrija o que for preciso e mude `status: proposed` para `status: approved`.
3. Colunas em `missing_columns` e as `questions` de cada arquivo estão consolidadas em `docs/open-questions.md`.
4. Depois da revisão, `dist\gateway.exe doctor` deve mostrar `[OK] arquivos de tabela 46 tabelas com arquivo aprovado`.
